# codesweep v2: one binary, one parser

Supersedes `plans/v1.md`, whose central structure does not survive measurement.
Everything below was checked against the installed tools rather than reasoned
about, and the checks are named so they can be repeated.

## What v1 got wrong

v1 describes three layers: syntactic enumeration by ast-grep, structural
relationships by `scanner-core`, and symbol resolution by SCIP. The middle
layer does not exist.

`scanner-core`'s `CallSite.callee` holds the raw source text of the call
expression and the crate performs no scope analysis. It matches names. ast-grep
matches names. They are the same layer with different output shapes, and both
are tree-sitter underneath. v1 says as much in passing and then builds a phase
on the distinction anyway.

Demonstrated: ast-grep answers the question phase 3 exists for, today, with no
new code, returning every call site of a name with its file, line and enclosing
function, and correctly skipping an object property of the same name. It does
this across 23 languages where `scanner-core` covers 6.

v1's stated reason for reaching for `scanner-core` is that it exists, builds
clean, and has been unused since December. That is sunk cost, not architecture.

## The decision

codesweep becomes a single Rust binary. ast-grep moves from an external command
to a linked library. `scanner-core` is not used and comes back out.

| Need | v1 | v2 |
|---|---|---|
| Parse many languages without comment or string noise | ast-grep binary, 23 languages | `ast-grep-core`, same engine, in-process |
| Express a rule people can read and version | ast-grep YAML | unchanged, loaded by `ast-grep-config` |
| Enumerate matches deterministically | subprocess and JSON | direct call |
| Stable site identity across reformatting | `hashlib` | `sha2` |
| Persist candidate set and verdicts | `sqlite3`, stdlib | `rusqlite`, bundled |
| Coverage arithmetic and reporting | Python | Rust |
| File discovery honouring ignore rules | shell out to `git ls-files` | the `ignore` crate |
| What calls this, what a change touches | `scanner-core`, 6 languages | ast-grep rules, 23 languages |
| Command surface | `argparse` | `clap` |
| Guidance the model reads | SKILL.md | unchanged |

## Evidence

**The library loads existing rules unchanged.** A spike built against
`ast-grep-core`, `ast-grep-config` and `ast-grep-language` 0.45.3 loaded
`rules/ts-catch-clause.yml` verbatim and returned the same three matches the
binary returns on the same fixture, including the brace form and a clause split
across lines. About forty lines of Rust. No rule migration is needed.

**The result is self-contained.** The installed ast-grep binary, built from
these crates, links only `libiconv` and `libSystem`. No Python, no Node, no
dynamically loaded grammars. Users install one file instead of three, and the
"ast-grep is not on PATH" refusal path disappears because nothing is left to be
missing.

**The language menu becomes a compile-time choice.** `ast-grep-language` exposes
each of 27 grammars as its own cargo feature. v1 wanted a menu and put it at a
layer where it protected nothing; here it decides binary size, which is 44MB
with all of them.

**scss is absent from that feature list**, confirming for a second time, by a
different route, that it must come out of the language map. Pointing it at the
CSS grammar is not a fix: on a six-line SCSS file the CSS grammar returns two of
three declarations and drops the one using a Sass variable, silently.

## Why not stay on Python

The Python CLI is stdlib-only and has no dependencies, so the usual argument
against it does not apply. Two things decide it anyway. Keeping Python while
adding any Rust gives two toolchains and two parser stacks for one job. And the
plugin currently ships guidance with nothing executable behind it, so packaging
has to be solved regardless; solving it once for a single artifact is simpler
than solving it for a script plus a binary plus an external dependency.

The cost is real and is not hidden: about 1100 lines to port with 103 tests
behind them, four platform builds or a Rust toolchain on the user's machine, and
a plugin that carries a binary rather than a script.

## Consequences for the backlog

- The vendored `crates/scanner-core` comes out. The tsx defect fixed in it was
  real and the fix was correct; the crate is simply not needed here.
- The caller and change-impact commands become rule templates run in-process,
  not a separate indexer with its own binary.
- Removing scss stands, now with two independent reasons.
- The eval work is unaffected in substance. Its packaging changes, because the
  plugin must carry a binary.
- SCIP remains the only real second layer, and remains deferred.

## The defect that outranks all of this

The plugin ships SKILL.md and nothing else. The skill issues eight `codesweep`
commands and its Requirements section names only ast-grep. Anyone installing the
plugin without running `install.sh` gets a protocol for a command they do not
have. Observed directly in an eval run, where the agent noticed, said so, and
improvised with ast-grep by hand.

Fix that first, under either architecture: ship the executable with the plugin,
and have the skill verify it resolves before step one, the way it already treats
a missing ast-grep.
