# codesweep: the structural layer, and proving the journey

## Context

**What exists.** codesweep enumerates every candidate site matching a syntactic
rule, an agent judges each one, and coverage is arithmetic. It is installed,
pushed to github.com/boxabirds/codesweep, and 103 tests pass across three suites.
The README carries a journey run end to end against axios that ends in a real
bug in axios's interceptor error path.

**What is missing, and why it matters.** That covers auditing. It does not cover
refactoring, which was the original ask. Today the skill explicitly refuses
"rename this", "find every caller", and "what breaks if I delete this", because
ast-grep does no scope analysis and cannot tell one `save` from another.

**The three layers, now understood.** Conflating them is what went wrong.

| Layer | Answers | Needs | State |
|---|---|---|---|
| Syntactic enumeration | every site of a shape | nothing | done, ast-grep |
| Structural relationships | what calls this, roughly | a parse | **not built**, `scanner-core` exists unused |
| Symbol resolution | what calls this, exactly | a working build | not built, SCIP |

The operator's own `scanner-core` at `~/expts/codemine/crates/scanner-core` is
the second layer and has been sitting unused since December 2025. I bypassed it
for ast-grep and did not return to it. It builds clean: 105 of 105 tests pass,
verified.

It does not do resolution either. Its `CallSite.callee` is the raw source text of
the call expression (`parser.rs:723`), with no scope analysis anywhere in the
crate. So it is a name-keyed graph, which is a heuristic that resembles
resolution. That is a property of tree-sitter, not of the code: GitHub built
`stack-graphs` to do resolution on tree-sitter without a compiler, and archived it
on 9 September 2025.

**Intended outcome.** Structural questions get answered approximately with the
approximation stated, instead of refused. The journey in the README extends from
"find every site of a shape" to "find everything that touches this symbol", with
each answer labelled by which layer produced it.

## Phase 1: fix the tsx bug in scanner-core

Do this before building anything on top.

`languages.rs:30` maps both `ts` and `tsx` to `Language::TypeScript`, and
`languages.rs:55` resolves that to `tree_sitter_typescript::language_typescript()`.
Proven through the same grammars via ast-grep: on a source file containing a JSX
element and a catch clause, the typescript grammar yields 0 matches and the tsx
grammar yields 1.

Tree-sitter emits error nodes rather than raising, so a `.tsx` file counts as
parsed and contributes zero symbols. Silent, and the same bug class codesweep
shipped with its own `language: typescript` rule.

- Add `Language::Tsx`, map `tsx` to it, bind it to `language_tsx()`.
- Add a test asserting a JSX file yields a non-zero symbol count, which fails
  before the change.
- Consider a parse-health signal on the index: a file whose tree contains error
  nodes should be reported, not counted as clean.

## Phase 2: give scanner-core a CLI

The crate is an rlib with no binary. `crates/scanner-py` already exposes it to
Python via pyo3, so the extraction API is proven; this adds a JSON surface.

New `crates/scanner-cli` with one command:

```
scanner-cli index <path> --json
```

Emitting symbols, call sites, inheritance edges and imports from the existing
`SymbolIndex`. No new analysis. Reuse `parse_file` and `SymbolIndex` from
`scanner-core/src/{parser,index}.rs` unchanged.

Respect `.gitignore` the way codesweep's `scope_extensions` already does, via
`git ls-files` inside a work tree, and report which discovery method was used.

## Phase 3: two new codesweep commands

`codesweep calls <name> --root <repo>` and `codesweep impact <symbol> --root
<repo>`, both shelling out to `scanner-cli` the way `run_rule` already shells out
to ast-grep in `bin/codesweep`.

**Every answer states its derivation.** Not decoration, the whole point:

```
calls: createProject          derivation: name-matched, not resolved
  workers/taskmgr/src/api/projects.ts:262   in createProjectHandler
  ...
14 call sites. A different function of the same name is indistinguishable from
this one. For an exact answer use a language server.
```

Follow the existing pattern where the census names its rules and the report
reproduces them: the claim and its limit travel together.

Skill changes: a section on structural questions, what the two commands answer,
and an explicit instruction that the derivation line is repeated to the operator
rather than dropped. The description's symbol-resolution exclusion softens from
"refuses" to "answers, name-matched, verify before acting" — and that wording
must be re-measured, since five probe rounds showed every edit to it introduced
the next defect.

## Phase 4: the language menu, at one layer only

Verified by testing each language against ast-grep: 23 of the 24 in codesweep's
`LANGUAGE_EXTENSIONS` are built in. `scss` is not, and is a bug to remove.

So enumeration needs no menu; a toggle there protects nothing. `scanner-core`
covers six languages and builds in seconds, so gating those behind cargo features
is premature. Ship all six with tsx fixed.

The menu belongs to Phase 5, where each indexer is a separate binary with its own
toolchain. Default on: TypeScript, JavaScript, Python. Present and off: Rust, Go,
C#, PHP, and the rest.

## Phase 5: SCIP, the resolution layer

Deferred deliberately, and the largest of the three.

`scip-typescript` is active and emits a language-agnostic protobuf index with
definition and reference roles. It requires `npm install` first, because it drives
the real compiler.

The design constraint that matters: it **fails silently incomplete** when a
project does not resolve. Whatever consumes it must detect and report that, or it
reproduces the tsx bug at a higher altitude.

Complementary rather than competing. SCIP is precise and needs a healthy build.
`scanner-core` is approximate and works on a half-refactored tree with no
dependencies installed, which is exactly when someone is asking.

## Phase 6: the eval suite

`claude plugin eval` exists and is not gated. It is the right harness and nothing
bespoke should be built.

- `tool_used` grader with `tool: Skill` asserts the skill fired.
- `--ablation with-without` runs a no-plugin baseline arm and reports the delta,
  which measures value rather than correctness. This is the operator's actual
  requirement: not "was the answer right" but "was it better than not having it".
- Isolation via `--bare`, a fixture `CLAUDE_CONFIG_DIR`, and `--plugin-dir`, so a
  run sees only the skill under test. Without this the real `~/.claude` leaks in
  and the result proves nothing.

Fixture: axios, already cached at `~/.cache/github/axios/axios`, pinned to
`8092aee7240220aa7913d163187b7fba8d9e5a51` so counts are stable. Reuse the
clone-and-skip-on-network-failure pattern from
`~/expts/codemine/cbr/tests/test_axios_integration.py`.

Cases should assert the journey, not the CLI: the skill fires, a census runs, a
manifest is taken before judging, and the final claim matches `status`. The two
axios findings are known-good answers to grade against.

No `case.yaml` exists anywhere on this machine, so start with
`claude plugin eval init --bare`.

## Verification

1. `cargo test -p scanner-core` — the tsx test fails before Phase 1, passes after.
2. Index a React tree with `scanner-cli` and confirm a non-zero symbol count from
   `.tsx` files, which is zero today.
3. `codesweep calls` against a symbol with a known call count in the Ceetrix repo,
   cross-checked with ripgrep, with the delta explained rather than tolerated.
4. `codesweep calls save` against a deliberately ambiguous name, confirming the
   derivation line appears and the answer is not presented as exact.
5. `tests/run-all.sh` stays green, with new suites for the two commands.
6. Re-measure the skill description against the trigger probe set after the
   exclusion wording changes.

## Sequence

Phases 1 to 3 deliver the missing half and use the operator's own code. Phase 4
is a small correction. Phase 5 is a separate project. Phase 6 proves the journey
and should follow the structural layer, since certifying a half-built tool
measures the wrong thing.
